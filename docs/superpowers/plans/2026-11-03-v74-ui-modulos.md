# v74 — primeira entrega da divisão do `app.js` — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** tirar do `js/app.js` as áreas avisos, observabilidade, aparência, dados, exportações e compartilhar, transformando cada uma num módulo `js/modules/ui/*.mjs`, sem nenhuma mudança visível. A prova é um teste de equivalência permanente.

**Architecture:** cada módulo exporta uma fábrica `criarX(ctx)`, no padrão do `pwa.mjs`. O `app.js` cria um objeto `estado` (getters/setters das variáveis atuais), instancia as fábricas no topo da IIFE, na ordem avisos → observabilidade → aparência → dados → exportações → compartilhar, e repassa a cada uma o que ela usa. Um módulo de UI nunca importa outro módulo de UI.

**Tech Stack:** HTML/CSS/JS sem build, módulos ES, Chrome headless via CDP (testes), Node ≥ 22.

**Spec:** `docs/superpowers/specs/2026-11-03-app-js-modulos-ui-design.md`

## Global Constraints

- Zero dependências em produção; CSP e `index.html` inalterados, exceto pelo bump de versão.
- Nenhuma mudança de comportamento, texto ou visual. `#dialogNovidades` sem item novo; `data-conteudo="71"` mantido.
- Mover código **sem reescrever a lógica**. Só mudam as referências a estado (`escalas` → `estado.escalas` etc.) e a origem das dependências (vindas de `ctx`).
- Fábricas não tocam o DOM na criação. Só definem funções; o trabalho acontece quando o `init()` ou um evento as chama.
- Todo módulo novo entra no `SHELL` do `sw.js`.
- `npm run verify` e `node tests/equivalencia.mjs` verdes ao fim de cada tarefa. Antes de cada `git add`, rodar `git checkout -- artifacts/`.
- Commits em português no estilo do histórico; versão final **v74**.

## Review Focus

1. **Escrita de estado esquecida:** uma função movida que ainda faz `escalas = …` em vez de `estado.escalas = …` gravaria numa variável local, e a tela não atualizaria (ex.: restaurar backup). O teste da Task 4 restaura um backup pela fábrica e confere `estado.escalas`.
2. **Fila de toasts duplicada:** se algum módulo criar a própria fila, os avisos se sobrepõem. A Task 2 garante que `criarAvisos(` aparece uma única vez fora do próprio módulo (no `app.js`).
3. **Erros de carregamento sem registro:** se `initObservabilidade` passar a rodar depois de outro módulo que falha, o erro some do `__ac4Erros()`. A Task 3 confere que `window.__ac4Erros` existe após o carregamento do `app.js` no Node e que `initObservabilidade` é a primeira chamada do `init()`.
4. **Ganchos de teste perdidos:** `__ac4LembrarBackup` e `__ac4SimularAtualizacao` precisam continuar expostos em localhost depois de mover `lembrarBackup`. Já é coberto pelo smoke (lembrete de backup) e pelo teste "Ganchos de teste restritos a localhost", que precisa passar a varrer `js/modules/ui/` (Task 1).
5. **Arquivo `.ics` e links de agenda:** são o que o policial importa no calendário; uma mudança sutil não aparece nos testes de fluxo. O teste de equivalência captura o `.ics` baixado e o HTML do diálogo de provedores, com os links Google e Outlook (Task 1).

```js
const MODULOS_UI = { avisos: ['toast', 'dialogConfirmar', 'haptic'] };
const validarModulosUI = async () => {
  const app = readFileSync(join(raiz, 'js', 'app.js'), 'utf8');
  const falhas = [];
  for (const [nome, chaves] of Object.entries(MODULOS_UI)) {
    const mod = await import(pathToFileURL(join(raiz, 'js', 'modules', 'ui', `${nome}.mjs`)).href);

    const api = fabrica(new Proxy({}, { get: () => () => {} }));
```

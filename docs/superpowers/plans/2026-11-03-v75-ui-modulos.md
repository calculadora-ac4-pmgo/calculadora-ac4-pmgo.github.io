# v75 — segunda entrega da divisão do `app.js` — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** concluir a divisão do `js/app.js` (1.234 linhas na v74) movendo planejamento, formulário/lançamento e modelos favoritos para `js/modules/ui/`, junto com os eventos de cada área, até o `app.js` ficar só com estado, ligação dos módulos, `render()` e um `init()` curto. Nada pode mudar para o usuário.

**Architecture:** o mesmo padrão da v74. Cada módulo exporta uma fábrica `criarX(ctx)`, recebe o objeto `estado` e as funções de que precisa, e não importa outro módulo de UI. Cada fábrica da v75 também devolve `ligarEventos()`, que o `init()` chama, tirando do `init()` os `on(...)` da própria área. Ligações entre áreas (compartilhar → exportações/dados) continuam no `init()`, porque a ligação é o papel do `app.js`.

**Tech Stack:** HTML/CSS/JS sem build, módulos ES, Chrome headless via CDP, Node ≥ 22.

**Spec:** `docs/superpowers/specs/2026-11-03-app-js-modulos-ui-design.md`

## Global Constraints

- Zero dependências em produção; CSP inalterada; nenhuma mudança de comportamento, texto ou visual; `data-conteudo="71"` mantido.
- Mover código **sem reescrever a lógica**. Trocas de nome **só em código**, nunca em textos (armadilha registrada na v74). Conferir com o teste de literais da Task 1.
- Fábricas não tocam o DOM ao serem criadas.
- Consts do `app.js` declaradas mais abaixo vão como funções de chamada tardia.
- Todo módulo novo entra no `SHELL` do `sw.js`.
- A cada tarefa: `node tests/run-tests.mjs`, `node tests/equivalencia.mjs` e `npm run test:smoke` verdes. Se o smoke oscilar nos 5 passos conhecidos (PDF/histórico/lembrete), repetir uma vez.
- Antes de cada `git add`, rodar `git checkout -- artifacts/`. Commits em português; versão final **v75**.

## Decisão de divisão (dentro do contrato da spec)

A spec lista `formulario` com modelos, repetir, duplicar, remover e limpar. Juntos, dariam cerca de 520 linhas, que é o tipo de arquivo grande que a refatoração quer evitar. Por isso os **modelos favoritos** vão para um módulo próprio, `ui/modelos.mjs` (~100 linhas). As responsabilidades continuam as da spec; muda só o número de arquivos (9 em vez de 8).

## Review Focus

1. **Textos alterados ao mover:** é o incidente da v74. A Task 1 cria um teste permanente que compara todos os literais de `js/app.js` + `js/modules/ui/*.mjs` com a referência da v74. Para que a troca legítima `${escalas}` → `${estado.escalas}` não acuse diferença, `estado.` é ignorado **só dentro de `${…}`**.
2. **Escrita de estado sem `estado.`** (`editandoId = …`, `submetendo = …`, `sheetAberto = …`, `filtroMes = …`, `ultimaExcluida = …`): gravaria numa variável inexistente. O ESLint `no-undef` acusa, e a Task 2 acrescenta à suíte de módulos uma varredura explícita de atribuições nuas nos arquivos de `ui/`.
3. **Teclado no sheet do celular** (Tab preso no painel, Esc fecha, Ctrl/Cmd+Enter envia): o listener `keydown` vai para `formulario.ligarEventos()`. É coberto pelo smoke e pelo `mobile-check` (sheet abre e fecha, foco). Conferir que o listener continua sendo registrado uma única vez.
4. **Filtros e planejamento:** as mudanças em `#filtroMes`, origem, situação e busca precisam continuar gravando em `estado.filtroX` antes do `render()`. O estado B da equivalência troca o mês pelo próprio `<select>` e cobre esse caminho.
5. **Atualização vinda de outra aba (`storage`):** fica no `app.js`, mas passa a chamar `cancelarEdicao` vindo de `formulario`. Coberto pela leitura do código no fim da Task 3: o handler precisa usar a função devolvida pela fábrica.
